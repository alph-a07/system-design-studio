Getting Started

System Design Studio Quickstart

System Design Studio operates on a Project-as-a-Learning-Instance model. Rather than relying on external cloud accounts or web portals, all progress and running context live inside a local .system-design/ folder in your project repository.

bash · 1-command setup 
# 1. Initialize inside any existing project or new folder
curl -fsSL https://raw.githubusercontent.com/alph-a07/system-design-studio/main/skills/system-design-studio/scripts/init-learning-instance.sh | bash

# 2. Open with your AI coding agent (Antigravity, Cursor, Claude Code)
Prompt: "Let's continue our system design learning from where we left off."

# 3. Check status report anytime
python3 skills/system-design-studio/scripts/sync-status.py .system-design

The Project-as-a-Learning-Instance Architecture

When initialized, the studio scaffolds five distinct plain-text artifacts inside your repository:

.system-design/manifest.json: Machine-readable JSON tracking completion states, verified evidence, examples registry, and deferred queue.
.system-design/CURSOR.md: The living operational brain read by AI agents on cold startup. Contains active focus, backward anchors, and next teaching actions.
.system-design/CURRICULUM.md: The master 50-cluster syllabus with 354 topics and verified checkboxes (- [x]).
.system-design/DECISIONS.md: Portfolio of accepted Architecture Decision Records (ADRs) defended by the learner during workshops.
.system-design/lessons/: Standalone interactive HTML lesson artifacts with embedded JavaScript simulators.

The Living Cursor Engine

AI chat threads suffer from cognitive amnesia: context windows get compacted, chat sessions are cleared, or developers switch between models (e.g. Gemini ➔ Claude ➔ GPT-4o). The Living Cursor solves this by serializing cognitive continuity into four structured sections:

  • 1. Active Focus: Exact cluster ID, active topic ID, topic foundation status, and the immediate next teaching action.
  • 2. Connected Cognitive Lineage: Backward anchor (where we came from and what physical force forced the current mechanism) and forward hook (what is unlocked next).
  • 3. Examples Registry (examplesTaken): Logs concrete engineering domains (e.g. Financial Ledger, Telemetry Stream) so the tutor can either deepen the same system or contrast against opposing workloads.
  • 4. Deferred Topics Queue (deferredQueue): Logs advanced forward-looking questions asked by the learner. When the target cluster arrives, the queue rehydrates the question and closes the loop.

CLI Command Reference

All scripts are written in standard Python 3 and Bash with zero external pip dependencies.

advance-cursor.py

Idempotently advances the cursor state, updates manifest.json, regenerates CURSOR.md, and marks completion in CURRICULUM.md. 

python3 scripts/advance-cursor.py \
  --complete-topic topic.0.1.tcp-vs-udp \
  --evidence "Learner traced TCP receive window bufferbloat" \
  --log-example-domain "Financial Ledger" \
  --log-example-scenario "Payment idempotency retry on socket timeout" \
  --next-topic-id topic.0.1.http-1-1-vs-http-2-vs-http-3 \
  --next-action "Establish topic foundation for HTTP/1.1 vs HTTP/2 vs HTTP/3" \
  --lesson-artifact .system-design/lessons/topic-0.1-tcp-vs-udp.html

sync-status.py

Instant terminal diagnostic reporting active topic, progress percentage, examples count, and pending deferred questions. 

python3 scripts/sync-status.py .system-design

verify-instance.py

Automated health-check testing JSON schemas, checkbox parity, lineage consistency, and HTML artifact validity. 

python3 scripts/verify-instance.py .system-design

import-curriculum.py (BYO)

Parses any custom Markdown syllabus and scaffolds a complete learning instance. 

python3 scripts/import-curriculum.py --input my-team-syllabus.md --instance-dir .system-design

Bring-Your-Own (BYO) Customization

System Design Studio is completely curriculum-agnostic. You can supply your own engineering syllabus using standard Markdown headers: 

# Cloud-Native Systems Engineering

## Cluster 1: Service Mesh Architecture & Data Plane
- [ ] Envoy filter chains, listener architecture, and thread models
- [ ] Mutual TLS (mTLS) performance and SPIFFE/SPIRE workload identities
- [ ] Circuit breaking thresholds, outlier detection, and panic routing

## Cluster 2: Consensus & Sharding
- [ ] Raft leader leases vs Paxos round-trip costs
- [ ] Two-phase commit (2PC) vs Saga orchestration patterns

Agent Environments & Installation

Google Antigravity: Install via agy plugin add https://github.com/alph-a07/system-design-studio.git. Interactive HTML lessons render directly in the host side pane.
Claude Code: Clone to ~/.claude/skills/system-design-studio. Full CLI execution with automated git commits.
Cursor: Add as submodule in .cursor/skills/system-design-studio or copy into workspace rules.
OpenAI Codex & Gemini CLI: Drop the folder into your local repository workspace.
