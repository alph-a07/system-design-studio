Section 01 • Architecture

System Design Studio Manual

Technical reference for stateful systems architecture pedagogy with AI coding agents. Grounded in hardware latencies, recorded in local Git repository files, and verified via executable visual artifacts.

Architectural Philosophy

1. File-Based State

All learner state is stored in CURSOR.md. Agent context resets do not erase progress.

2. Hardware Anchored

Every architectural claim must trace back to physical numbers: L1 cache, DRAM, NVMe, WAN roundtrips.

3. Executable Artifacts

The agent must generate standalone HTML simulators with state machines for visual interaction.

Section 02 • Quickstart

Quickstart Installation

Scaffold a learning instance in your active repository using the standalone bash installer. The script creates the local .system-design/ directory structure and pulls templates from the canonical repository:

$ curl -fsSL https://raw.githubusercontent.com/alph-a07/system-design-studio/main/skills/system-design-studio/scripts/init-learning-instance.sh | bash
Prerequisites: Git, Bash 4+, Python 3.8+ (no pip modules required). View init script source →
Section 03 • Workspace

Where to Place the Learning Instance

Do I put this in my work repository? We recommend creating a dedicated learning repository:

# Option A (Recommended): Dedicated learning workspace

mkdir ~/learning/system-design && cd ~/learning/system-design && git init

curl -fsSL https://raw.githubusercontent.com/alph-a07/system-design-studio/main/skills/system-design-studio/scripts/init-learning-instance.sh | bash

If you run inside an existing work repository, add .system-design/ to your .gitignore:

# Option B: Add to work repo .gitignore

echo ".system-design/" >> .gitignore

Section 04 • Filesystem

Filesystem Contract

All instance state is stored locally within the repository under .system-design/. No third-party servers, cloud databases, or background daemons are used:

.system-design/ ├── manifest.json # Canonical curriculum index, prerequisite DAG & topic specs ├── CURSOR.md # Active learner state: focus, hardware anchors, queue ├── history.log # Append-only chronological audit log of completed topics ├── lessons/ # Standalone interactive HTML visual simulations └── scripts/ # Zero-dependency verification and sync automation ├── sync-status.py # Validates DAG, hardware anchors & manifest state ├── advance-cursor.py # Transitions topics and appends to audit log └── verify-instance.py # Healthcheck verification for CI & learners
Section 05 • State Engine

The CURSOR.md State Engine

Every AI agent session begins with reading .system-design/CURSOR.md. This replaces reliance on ephemeral LLM memory with file-backed persistence:

Layer 1: activeFocus

Current topic ID, tier, and depth level. Enforces laser focus on active concepts.

Layer 2: causalAnchors

Physical constraints and verified trade-offs established in past lessons.

Layer 3: examplesTaken

List of previously used analogies and domain examples to avoid repetitive explanations.

Layer 4: deferredQueue

Buffer for tangent questions. Captured without derailing the active topic focus.

Section 06 • Pedagogy

Pedagogical Protocol & Visual Artifacts

System Design Studio enforces a 3-phase pedagogical protocol to prevent agents from defaulting to superficial summaries:

Phase 1: Foundation (Hardware Constraints)

Ground every system mechanism in physical hardware limits (L1, DRAM, disk, network round trips).

Phase 2: Mechanics (State Transitions & Failures)

Walk through concrete message sequence charts, boundary failure modes, and race conditions.

Phase 3: The Trap (Reality Check & Artifact)

Present a subtle engineering trap. The agent generates a standalone interactive HTML visual artifact simulating the failure mode.

Section 07 • Automation

CLI Tools Reference

Built-in zero-dependency Python and Bash scripts inside .system-design/scripts/:

sync-status.py

Validates prerequisite topological DAG order, checks topic state, and confirms that active latency claims match hardware anchors.

python3 .system-design/scripts/sync-status.py
advance-cursor.py

Advances the learning state to the next prerequisite topic, updates CURSOR.md, and logs completion to history.log.

python3 .system-design/scripts/advance-cursor.py topic.0.1.http-v1-v2-v3
verify-instance.py

Automated healthcheck that verifies the manifest, CURSOR.md schema, and DAG validity. Used in CI workflows.

python3 .system-design/scripts/verify-instance.py

Section 09 • Customization

Bring Your Own Curriculum (BYO)

You can replace or augment the default 50-cluster syllabus with company engineering guidelines or architectural review checklists:

$ python3 .system-design/scripts/import-curriculum.py path/to/custom-syllabus.json

The importer validates cycle-free DAG topology and regenerates manifest.json automatically.
