System Design Studio Manual

A complete technical reference for embedding stateful systems architecture pedagogy into AI coding agents.

Architectural Philosophy

System Design Studio is built on a single realization: ephemeral AI chat threads are fundamentally incapable of teaching systems design. Systems engineering requires progressive cognitive lineage—remembering what hardware trade-offs were previously established, what failure modes the learner already struggled with, and what real-world analogies have already been exhausted.

By anchoring state to local Git files inside .system-design/, learning persists across model upgrades, context window resets, and development session breaks.

Quickstart Installation

Initialize a learning instance in your current working repository using the bootstrap installer:

curl -fsSL https://raw.githubusercontent.com/alph-a07/system-design-studio/main/skills/system-design-studio/scripts/init-learning-instance.sh | bash

The script creates the .system-design/ folder hierarchy, populates the 50-cluster syllabus, configures the living cursor, and automatically configures your AI agent instruction files (such as CLAUDE.md, AGENTS.md, or .cursorrules).

Filesystem Contract

All instance state is stored locally within the repository under .system-design/. No third-party servers, cloud databases, or API keys are required.

.system-design/ ├── manifest.json # Instance metadata, schema version, active curriculum ├── CURSOR.md # The living cognitive state engine (read on every prompt) ├── CURRICULUM.md # Complete topic index with status (unseen/in-progress/mastered) ├── DECISIONS.md # Architectural decision records (ADRs) authored by the learner ├── notes/ # Learner's personal markdown notes and study summaries └── lessons/ # Interactive self-contained HTML visual artifacts generated by agents

Core Files Specification

  • manifest.json: Stores the instance UUID, creation timestamp, curriculum version, and verification hashes.
  • CURSOR.md: The single source of truth for conversational context. Contains the active topic, verified causal anchors, used examples, and deferred tangents.
  • CURRICULUM.md: The indexed syllabus checklist. Topic statuses transition strictly from unseen → in-progress → mastered.
  • DECISIONS.md: Persistent ADR log capturing architectural trade-offs resolved during hands-on exercises.

The CURSOR.md State Engine

Every AI agent prompt session begins with reading .system-design/CURSOR.md. This replaces reliance on ephemeral LLM memory with deterministic file-backed state.

activeFocus: topicId: "topic.0.1.tcp-vs-udp" tier: "L0: Transport" phase: "mental-model-verified" depthLevel: "physical-mechanics" causalAnchors: - "100ms WAN RTT = 3 round trips before first byte on cold TCP+TLS" - "Head-of-Line blocking is physical in single-stream TCP sockets" - "UDP has zero transport state; congestion control lives in user-space" examplesTaken: - "postal-packet-delivery" - "airport-security-handshake" deferredQueue: - "QUIC connection migration across WiFi/Cellular shifts"

State Mutation Rules

Agents are instructed to update CURSOR.md only when tangible milestones occur:

  1. Active Topic Advancement: Triggered via advance-cursor.py only after the learner successfully passes Socratic trade-off validation.
  2. Causal Anchor Addition: Recorded immediately when a physical constraint (e.g. latency, disk write amplification) is proved.
  3. Example Registration: Logged whenever an analogy is drawn to guarantee pedagogical variety.

Pedagogical Protocol & Visual Artifacts

System Design Studio enforces a strict pedagogical protocol designed to prevent AI agents from falling back into generic summarization.

The Teaching Loop

  • 1. Socratic Probe: The agent tests existing learner intuition with a concrete physical trade-off question before explaining concepts.
  • 2. Mental Model & Mechanics: The concept is explained through hardware constraints (CPU, RAM, Disk, Network) rather than abstract architecture buzzwords.
  • 3. Interactive Visual Artifact: The agent writes a self-contained HTML file to .system-design/lessons/ with visual flow diagrams or failure simulators.
  • 4. Pressure Testing: The agent introduces an unexpected production failure (e.g. partition, packet drop, disk full) and asks the learner to defend their design.

CLI Tools Reference

System Design Studio provides standalone Python and Bash scripts inside skills/system-design-studio/scripts/:

init-learning-instance.sh

Initializes a fresh .system-design/ instance in the target directory and links agent instruction rules.

bash skills/system-design-studio/scripts/init-learning-instance.sh [target_dir]

advance-cursor.py

Advances the cursor to the next sequential topic or a specified target topic ID, updating both CURSOR.md and CURRICULUM.md.

python3 skills/system-design-studio/scripts/advance-cursor.py .system-design/ [optional_topic_id]

sync-status.py

Validates the consistency of the instance, reporting total progress, active focus, causal anchors count, and any structural warnings.

python3 skills/system-design-studio/scripts/sync-status.py .system-design/

verify-instance.py

Audits .system-design/ for schema compliance, unlinked topics, and missing cursor fields. Used in CI and automated hooks.

python3 skills/system-design-studio/scripts/verify-instance.py .system-design/

import-curriculum.py

Parses an external markdown syllabus and imports it into the standard System Design Studio schema.

python3 skills/system-design-studio/scripts/import-curriculum.py path/to/custom-syllabus.md .system-design/

System Design Studio works seamlessly across major agentic harnesses:

Google Antigravity

Install via the Antigravity Plugin Manager or command line:

agy plugin add system-design-studio

Anthropic Claude Code

Ensure your CLAUDE.md contains the System Design Studio instructions:

## System Design Studio When the user asks to learn or review system design: 1. Always read `.system-design/CURSOR.md` before responding. 2. Ground all discussions in physical hardware mechanics and latency numbers. 3. Deliver interactive HTML artifacts to `.system-design/lessons/`. 4. Run `python3 skills/system-design-studio/scripts/sync-status.py` to confirm state.

Cursor IDE

Add the rules to your repository's .cursorrules file to ensure Cursor agents respect the cursor lineage across conversations.

Bring Your Own Curriculum (BYO)

You can replace or augment the default 50-cluster syllabus with your company's internal engineering guidelines, architecture review checklists, or interview roadmaps.

Format your custom syllabus using standard Markdown heading levels:

# Custom Architecture Syllabus ## 1. Storage & Database Layer - [ ] B-Tree vs LSM write amplification - [ ] Read-after-write consistency in multi-region setups - [ ] Connection pool exhaustion and backpressure ## 2. Real-Time Streaming - [ ] Kafka consumer group rebalances - [ ] Exactly-once processing semantics

Then run the importer:

python3 skills/system-design-studio/scripts/import-curriculum.py my-syllabus.md .system-design/
