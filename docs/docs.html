System Design Studio Manual

Technical reference for stateful systems architecture pedagogy with AI coding agents.

Architectural Philosophy

Ephemeral AI chat threads lose context over time. Systems engineering requires cognitive continuity: remembering previous hardware trade-offs, past failure scenarios, and tested system domains.

By anchoring state to local files inside .system-design/, learning persists across model upgrades, context window resets, and development breaks.

Quickstart Installation

Scaffold a learning instance in your current working repository using the bootstrap installer:

curl -fsSL https://raw.githubusercontent.com/alph-a07/system-design-studio/main/skills/system-design-studio/scripts/init-learning-instance.sh | bash

View script first on GitHub

The script creates the .system-design/ folder hierarchy, copies the 50-cluster syllabus, populates the initial cursor, and creates the decision log. Note that init-learning-instance.sh scaffolds local files only; you must also register the skill with your AI agent as detailed in the Multi-Agent Integration guide below.

Where to Place the Learning Instance

Do I put this in my work repo? We recommend creating a dedicated learning repository:

mkdir ~/learning/system-design && cd ~/learning/system-design && git init

This keeps your personal study notes, architecture decisions, and generated HTML lessons in their own Git history. If you choose to scaffold inside an existing company or work repository, add .system-design/ to your .gitignore so your personal practice files stay out of team commits.

Filesystem Contract

All instance state is stored locally within the repository under .system-design/. No third-party servers, cloud databases, or API keys are required.

.system-design/ ├── manifest.json # Instance metadata, schema version, active curriculum ├── CURSOR.md # The living cognitive state engine (read on every prompt) ├── CURRICULUM.md # Complete topic index with status (unseen/in-progress/completed) ├── DECISIONS.md # Architectural decision records (ADRs) authored by the learner ├── notes/ # Learner personal markdown notes and study summaries └── lessons/ # Interactive self-contained HTML visual artifacts generated by agents

Core Files Specification

  • manifest.json: Stores instance UUID, creation timestamp, curriculum version, and verification metadata.
  • CURSOR.md: The authoritative file for conversational context. Contains the active topic, verified causal anchors, used examples, and deferred tangents.
  • CURRICULUM.md: The indexed syllabus checklist. Topic statuses transition from unseen → in-progress → completed.
  • DECISIONS.md: Persistent ADR log capturing architectural trade-offs resolved during hands-on exercises.

The CURSOR.md State Engine

Every AI agent prompt session begins with reading .system-design/CURSOR.md. This replaces reliance on ephemeral LLM memory with deterministic file-backed state.

# Sample CURSOR.md activeFocus: topicId: "topic.0.1.tcp-vs-udp" tier: "Tier 0 — HLD Building Blocks (Prerequisite Slice)" phase: "foundation-complete" depthLevel: "physical-mechanics" causalAnchors: - "Cold TCP + TLS 1.3 (no 0-RTT/resumption): 3 round trips before first byte" - "Head-of-Line blocking in single-stream TCP socket buffers" - "UDP has zero transport state; congestion control runs in user-space" examplesTaken: - "financial-ledger-wal" - "live-webrtc-audio" deferredQueue: - "QUIC connection migration across cellular handoffs"

State Mutation Rules

Agents update CURSOR.md when tangible milestones occur:

  1. Active Topic Advancement: Triggered via advance-cursor.py after the learner verifies the causal invariants.
  2. Causal Anchor Addition: Recorded immediately when a physical constraint (latency, disk write amplification) is proved.
  3. Example Registration: Logged whenever an analogy is drawn to maintain varied contexts.

Pedagogical Protocol & Visual Artifacts

System Design Studio enforces a structured pedagogical protocol to prevent agents from defaulting to generic summaries.

The Teaching Loop

  • 1. Socratic Probe: The agent tests existing learner intuition with a physical trade-off question before explaining concepts.
  • 2. Mental Model & Mechanics: The concept is explained through hardware constraints (CPU, RAM, disk, network).
  • 3. Interactive Visual Artifact: The agent writes a self-contained HTML file to .system-design/lessons/ with visual flow diagrams or failure simulators.
  • 4. Pressure Testing: The agent introduces an unexpected production failure (partition, packet drop, disk full) and asks the learner to defend their design.

CLI Tools Reference

System Design Studio provides zero-dependency Python and Bash scripts inside skills/system-design-studio/scripts/:

init-learning-instance.sh

Initializes a fresh .system-design/ instance in the target directory with syllabus and cursor templates.

bash skills/system-design-studio/scripts/init-learning-instance.sh [target_dir]

advance-cursor.py

Advances the cursor to the next sequential topic or a specified target topic ID, updating both CURSOR.md and CURRICULUM.md.

python3 skills/system-design-studio/scripts/advance-cursor.py .system-design/ [optional_topic_id]

sync-status.py

Diagnostic tool that reads .system-design/manifest.json and reports active cluster, active topic, foundation status, mechanism group, logged examples, and pending deferred questions.

$ python3 skills/system-design-studio/scripts/sync-status.py .system-design/ (sample output) ============================================================ SYSTEM DESIGN STUDIO — INSTANCE DIAGNOSTIC ============================================================ Instance Name: System Design Learning Instance Curriculum: System Design Roadmap (curriculum.system-design) Overall Progress: 28 / 354 Topics (7.9%) Breakdown: Completed=28 | In-Progress=1 | Unseen=325 (Sum: 354) ------------------------------------------------------------ Active Tier: Tier 0 — HLD Building Blocks (Prerequisite Slice) Active Cluster: 1. [0.1] APIs & Network Transport for Design Active Topic: TCP vs UDP — what reliability costs, and why real-time media often picks UDP Foundation: complete Mechanism Group: group.0.1.tcp-udp-foundations ------------------------------------------------------------ Examples Logged: 2 └─ Latest: [financial-ledger-wal] Strict sequence ordering vs datagram drops... Deferred Queue: 1 pending questions └─ Next Due: [cluster.0.1] QUIC connection migration across cellular handoffs ------------------------------------------------------------ Immediate Next Action: 👉 Evaluate checkpoint.0.1.tcp-head-of-line-blocking response ============================================================

verify-instance.py

Audits .system-design/ for schema compliance, unlinked topics, and missing cursor fields. Used in CI and automated hooks.

python3 skills/system-design-studio/scripts/verify-instance.py .system-design/

import-curriculum.py

Parses an external markdown syllabus and imports it into the standard System Design Studio schema.

python3 skills/system-design-studio/scripts/import-curriculum.py path/to/custom-syllabus.md .system-design/

Multi-Agent Integration Guides

Setup involves two steps: installing the skill into your AI agent, then running the scaffolding script in your learning repository.

Google Antigravity

Install via the Antigravity Plugin Manager or CLI, then scaffold your instance:

# Step 1: Install plugin into Antigravity agy plugin add alph-a07/system-design-studio # Step 2: Scaffold instance in your repo curl -fsSL https://raw.githubusercontent.com/alph-a07/system-design-studio/main/skills/system-design-studio/scripts/init-learning-instance.sh | bash

Anthropic Claude Code

Clone the skill to your Claude Code skills directory and run scaffolding:

# Step 1: Clone skill to Claude Code skills directory git clone https://github.com/alph-a07/system-design-studio.git ~/.claude/skills/system-design-studio # Step 2: Scaffold instance in your repo bash ~/.claude/skills/system-design-studio/skills/system-design-studio/scripts/init-learning-instance.sh

Cursor IDE

Add the skill as a git submodule and initialize the workspace:

# Step 1: Add submodule in your learning repo git submodule add https://github.com/alph-a07/system-design-studio.git .cursor/skills/system-design-studio # Step 2: Scaffold instance in your repo bash .cursor/skills/system-design-studio/skills/system-design-studio/scripts/init-learning-instance.sh

OpenAI Codex

Clone the repository, append the interaction contract to AGENTS.md, and run scaffolding:

# Step 1: Clone and add contract to AGENTS.md git clone https://github.com/alph-a07/system-design-studio.git /tmp/system-design-studio cat /tmp/system-design-studio/skills/system-design-studio/references/interaction-contract.md >> AGENTS.md # Step 2: Scaffold instance in your repo bash /tmp/system-design-studio/skills/system-design-studio/scripts/init-learning-instance.sh

Bring Your Own Curriculum (BYO)

You can replace or augment the default 50-cluster syllabus with company engineering guidelines, architecture review checklists, or interview roadmaps.

Format your custom syllabus using standard Markdown heading levels:

# Custom Architecture Syllabus ## 1. Storage & Database Layer - [ ] B-Tree vs LSM write amplification - [ ] Read-after-write consistency in multi-region setups - [ ] Connection pool exhaustion and backpressure ## 2. Real-Time Streaming - [ ] Kafka consumer group rebalances - [ ] Exactly-once processing semantics

Then run the importer:

python3 skills/system-design-studio/scripts/import-curriculum.py my-syllabus.md .system-design/
